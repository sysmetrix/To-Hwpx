# v4.13.0 변경 회귀 재분석 및 v4.13.1 전후 비교

검토일: 2026-07-12

| 점검 항목 | v4.13.0 변경 후 문제 | 원인 | v4.13.1 해결 | 검증 기준 |
|---|---|---|---|---|
| Windows vendor 무결성 | `npm run test:commercial`이 JSZip 등 4개 JS에서 SHA-256 불일치로 실패 | `core.autocrlf=true`인 Windows 체크아웃이 고정 vendor JS의 LF를 CRLF로 변환 | `.gitattributes`에서 `js/vendor/** -text`로 원본 바이트 고정 | Windows 로컬·Linux CI에서 동일 SHA-256, commercial gate PASS |
| 오픈소스·글꼴 고지 표시 | 푸터가 Markdown 원문을 직접 열어 일반 웹 문서처럼 읽기 어려움 | 운영 UI가 `THIRD_PARTY_NOTICES.md`를 직접 링크 | 반응형 `notices.html` 신설, 개인정보/약관/푸터 링크 통일 | axe WCAG AA, production smoke에서 HTTP 200 |
| 기존 고지 URL | 이미 배포된 `/THIRD_PARTY_NOTICES.md` 주소가 남아 혼선 가능 | 문서 URL 변경에 대한 호환 경로 없음 | Vercel에서 기존 주소를 `/notices.html`로 영구 이동 | production smoke가 최종 URL 확인 |
| 외부 GitHub 링크 | 정밀 미리보기 설명과 문의 문서가 GitHub로 이동 | 개발 단계 문의·원저작자 링크가 사용자 화면에 남음 | 사용자 HTML의 GitHub 링크 제거, rhwp는 일반 텍스트 설명으로 변경 | commercial/golden에서 `github.com` 링크 0개 |
| 외부 재단 링크 | 푸터와 개인정보 문서가 재단 홈페이지로 이동 | 운영 문의 대상을 외부 링크로 직접 연결 | 링크를 제거하고 외부 이동 없는 문의 안내로 변경 | commercial/golden에서 `bwyf.or.kr` 링크 0개 |
| 배포·오프라인 포함 | 새 HTML 고지가 Pages 배포와 PWA 캐시에 빠질 가능성 | 신규 정적 파일 allowlist 미갱신 위험 | Pages 복사 목록, 서비스워커 APP_SHELL, sitemap에 `notices.html` 추가 | commercial gate, 운영 HTTP/PWA 검사 |
| 회귀 방지 범위 | Markdown 링크/외부 링크 문제가 재발할 수 있음 | 기존 테스트가 파일 존재 위주 | 고지 HTML 접근성, 외부 링크 금지, 기존 URL 이동을 자동 검사 | golden·axe·commercial·production smoke |

## 결론

v4.13.0의 변환 기능과 운영 배포 자체는 정상이나, Windows 개발 환경의 vendor 해시 재현성과 법적 고지의 사용자 가독성에 회귀가 있었다. v4.13.1은 변환 IR/HWPX 구조를 바꾸지 않고 배포·고지·무결성 경계만 수정한다.
